## 一、核心架构决策汇总

| # | 决策 | 结论 |
|---|------|------|
| Q1 | 重写范围 | **只换前端**。Python 后端保留（工具链 + 多模态），JS 重写 UI 层 |
| Q2 | JS 框架 | **React/Next.js (App Router)** |
| Q3 | 通信协议 | **SSE**（Vercel AI SDK 原生支持） |
| Q4 | Agent 循环 | **AI SDK 接管**。Agno 退役，agent 循环由 Vercel AI SDK `useChat` + `maxToolRoundtrips` 管理 |
| Q5 | UI 组件库 | **Shadcn/ui + Aceternity UI** |
| Q6 | 页面布局 | **Chat 中心 + Detail Panel**（默认聊天气泡，选中视频时右侧展开详情面板） |
| Q7 | Tool Parser | **vLLM bare 模式 + SSE Relay**（删除 `--enable-auto-tool-choice` 和 `--tool-call-parser`） |
| Q8 | 工具接口 | **独立 REST 端点**（FastAPI 微服务） |
| Q9 | 仓库结构 | **Monorepo**（`frontend/` + `server/` + `src/`） |
| Q10 | vLLM grammar | **不启用**。vLLM 裸奔，模型自由输出 `<tool_call>` XML，代理层流式转换 |
| Q11 | vLLM 访问 | **浏览器直连**（AutoDL 公网 URL）。如遇证书问题再改代理 |
| Q12 | 状态管理 | **Zustand** |
| Q13 | 目录结构 | 标准 Next.js + Shadcn/ui 布局（见 §三） |
| Q14 | 代理载体 | **FastAPI 统一后端**（替换 `llama_proxy.py`） |
| Q15 | Tool Call 检测 | **前缀扫描**（缓冲 ~20 chars，检测 `<tool_call` 后切换缓冲模式） |
| Q16 | 总结进度 | **SSE 进度流**（`GET /api/tools/summarize/{id}/stream`） |
| Q17 | 部署 | **FastAPI → AutoDL**（与 vLLM 同机），**Next.js → Vercel** |
| Q18 | Tool 定义 | **Python 为单一真相源**（`GET /api/tools/definitions`） |
| Q19 | 图片传输 | **保持 base64**（`image_url` 内嵌，暂不引入上传服务） |
| Q20 | 实现顺序 | **Phase 1→2→3→4**（见 §七） |

## 二、系统架构图

```
┌────────── AutoDL 服务器 (RTX 3090 48GB) ──────────────┐
│                                                        │
│  vLLM-Omni :6006 (bare mode, 无 tool_choice/parser)    │
│  ├─ Agent 主模型（纯文本流式，天然输出 <tool_call>）     │
│  └─ 多模态模型（音频 + 帧 → 视频总结）                    │
│                                                        │
│  FastAPI :8000                                          │
│  ├─ POST /v1/chat/completions  → SSE Relay → vLLM      │
│  ├─ GET  /api/tools/definitions → 工具定义 JSON         │
│  ├─ POST /api/tools/download     下载视频               │
│  ├─ POST /api/tools/summarize    多模态总结（异步）      │
│  ├─ GET  /api/tools/summarize/{id}/stream 进度 SSE      │
│  ├─ GET  /api/tools/hot          热榜查询               │
│  ├─ GET  /api/tools/search       视频搜索               │
│  └─ GET  /api/tools/creator      创作者视频             │
│                                                        │
└────────────────────┬───────────────────────────────────┘
                     │ AutoDL 自定义服务 :8000 → :8443
                     │
┌────────── Vercel ──────────────────────────────────────┐
│                                                        │
│  Next.js (App Router)                                  │
│  ├─ useChat (Vercel AI SDK) → agent 循环               │
│  ├─ ChatView → 消息流 + 工具状态徽章                    │
│  ├─ DetailPanel → 视频播放 + 总结 + 思维导图            │
│  └─ Zustand stores → 布局状态 + 工具进度                │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### 数据流

```
1. 用户输入
   浏览器 → AI SDK useChat → POST /v1/chat/completions (FastAPI)

2. 模型推理
   FastAPI SSE Relay → vLLM :6006 (stream=true, bare mode)
   vLLM → SSE chunks (纯文本，可能含 <tool_call> XML)

3. SSE Relay 处理
   前缀扫描: 缓冲 20 chars
   ├─ 纯文本 → 透传 SSE chunks → AI SDK → UI 渲染
   └─ <tool_call> → 缓冲完整 XML → 提取 JSON → 构造 tool_calls delta SSE

4. 工具执行 (AI SDK 收到 tool_calls 后)
   AI SDK → POST /api/tools/{name} (FastAPI) → Python 工具执行 → 结果返回

5. 工具结果注入
   AI SDK 将 tool_result 注入 messages → 继续步骤 2 → 直到模型输出最终文本

6. 多模态总结 (独立路径，不走 agent 循环)
   AI SDK → POST /api/tools/summarize → 202 + task_id
   前端 → GET /api/tools/summarize/{id}/stream → SSE 逐 token
```

## 四、SSE Relay 设计

### 核心状态机

```
                    ┌──────────────┐
       start ──────→│ PASSTHROUGH  │
                    └──────┬───────┘
                           │ 检测到 "<tool_call" 前缀
                           ▼
                    ┌──────────────┐
                    │  BUFFERING   │
                    └──────┬───────┘
                           │ 匹配到完整 "</tool_call>"
                           ▼
                    ┌──────────────┐
                    │  CONVERTING  │ → 提取 JSON → 构造 tool_calls delta SSE
                    └──────┬───────┘
                           │
                           ▼
                    ┌──────────────┐
                    │ PASSTHROUGH  │ (继续处理后续文本)
                    └──────────────┘
```

### 前缀扫描策略

1. 向 vLLM 发送 `stream: true`（不传 `tools`/`tool_choice`）
2. 缓冲前 20 个字符（约 5ms @ 300 tok/s）
3. 判断：包含 `<tool_call` → 切换 BUFFERING；否则 → 透传缓冲 + 后续所有 chunk
4. BUFFERING 模式：累积所有 chunk 直到 `</tool_call>` 闭合
5. 用大括号计数算法提取 JSON，构造标准 OpenAI `tool_calls` delta
6. 以 SSE 格式流式发送：`data: {"choices":[{"delta":{"tool_calls":[{"index":0,"function":{"name":"...","arguments":"..."}}]}}]}`

### 关键实现细节

- HTTP/1.1 协议（OpenAI SDK 要求）
- `stream_options` 自动剥离
- 流式 tool_calls delta 的 `index` 字段必须正确
- 提取失败时回退为纯文本透传（容错）

## 五、工具端点 API 规范

### `GET /api/tools/definitions`

返回 OpenAI 兼容的工具定义列表，供 AI SDK `useChat` 使用。

```json
[
  {
    "type": "function",
    "function": {
      "name": "get_hot_videos",
      "description": "获取平台热门视频榜单",
      "parameters": {
        "type": "object",
        "properties": {
          "platform": { "type": "string", "enum": ["bilibili"], "description": "平台" },
          "limit": { "type": "integer", "default": 10, "description": "返回数量" },
          "date_filter": { "type": "string", "default": "today", "description": "日期筛选" }
        },
        "required": ["platform"]
      }
    }
  }
]
```

### `POST /api/tools/download`

```json
// Request
{ "video_url": "https://...", "file_name": "optional_name" }

// Response (同步)
{ "status": "ok", "local_path": "/workspace/video.mp4", "platform": "bilibili", "cached": false }
```

### `POST /api/tools/summarize`

```json
// Request
{ "local_path": "/workspace/video.mp4", "metadata": { "title": "...", "desc": "..." } }

// Response (异步)
{ "task_id": "uuid", "status": "processing", "stream_url": "/api/tools/summarize/uuid/stream" }
```

### `GET /api/tools/summarize/{task_id}/stream`

SSE 事件流：

```
data: {"type": "progress", "stage": "extracting_audio", "message": "正在提取音频..."}
data: {"type": "progress", "stage": "analyzing", "message": "正在分析关键帧..."}
data: {"type": "token", "content": "## 核心观点\n\n"}
data: {"type": "token", "content": "该视频主要..."}
...
data: {"type": "done", "result": "完整总结文本"}
```

### `GET /api/tools/hot`, `GET /api/tools/search`, `GET /api/tools/creator`

查询参数映射到现有工具签名，返回标准 JSON。

## 六、前端核心组件设计

### AppShell

```tsx
// 驱动混合布局
function AppShell({ children }) {
  const selectedVideoId = useLayoutStore(s => s.selectedVideoId)
  
  return (
    <div className="flex h-screen">
      <div className={cn("flex-1", selectedVideoId && "w-1/2 border-r")}>
        <ChatView />
      </div>
      {selectedVideoId && (
        <motion.div className="w-1/2" layout>
          <DetailPanel videoId={selectedVideoId} />
        </motion.div>
      )}
    </div>
  )
}
```

### ChatView

- 使用 `useChat()` from `@ai-sdk/react`
- `fetch` 指向 FastAPI `/v1/chat/completions`
- `maxToolRoundtrips: 5`
- 每条消息渲染 `ChatMessage`
- 工具调用显示 `ToolBadge`（⏳/✅ + 工具名）
- 视频卡片用 `VideoCard` 渲染，点击触发 `selectVideo(id)`

### VideoCard

- 显示封面缩略图、标题、时长徽章、AI 总结摘要（前 3 行）
- 点击 → `useLayoutStore.set({ selectedVideoId })` → 右侧面板展开
- Framer Motion `layoutId` 做卡片到面板的共享元素过渡

### DetailPanel

- Vidstack 播放器（全宽）
- AI 总结全文（Markdown 渲染）
- 未来扩展：React Flow 思维导图
- 关闭按钮 → `useLayoutStore.set({ selectedVideoId: null })`

### Zustand Stores

```ts
// layout store
interface LayoutState {
  selectedVideoId: string | null
  selectVideo: (id: string | null) => void
}

// tool progress store (补充 AI SDK 的 toolInvocations)
interface ToolProgressState {
  tasks: Map<string, { status: string; partial: string; result: string | null }>
  updateTask: (id: string, data: Partial<Task>) => void
}
```
