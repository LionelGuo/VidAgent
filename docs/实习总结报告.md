# VidAgent 实习总结报告

> 项目：智能自媒体数据采集与多模态分析 Agent 系统
> 周期：2026-07 ~ 2026-08 ｜ 硬件：RTX 4060 Laptop（8GB 显存）
> 状态：Sprint 1–3 完成，Sprint 4（本地化 / 扩平台）待启动

## 一、项目背景与目标

短视频时代，各平台每天产生海量内容，人工逐条观看、归纳成本极高。本项目旨在构建一套自动化系统：用自然语言下达指令，由智能体（Agent）自主调度爬虫、下载器、ASR、大模型，完成「采集 → 下载 → 转写 → 总结」全链路，输出结构化中文摘要。

核心目标：
1. **多平台**：先 B站，后扩展抖音 / 小红书 / 快手。
2. **场景化**：平台今日热门 Top N、指定创作者今日视频，均可一键总结。
3. **Agent 驱动**：打破命令行僵化，自然语言规划任务、调用工具。
4. **本地可部署**：8GB 显存下云端 / 本地大模型无缝切换。

## 二、系统架构

采用三层解耦：

- **交互层**：Gradio 对话界面，渲染 Markdown、内嵌播放本地视频。
- **调度层**：Agno Agent，负责意图识别、任务拆解、Function Calling、出错反思重试。
- **工具层**：Crawler（爬虫适配）、Downloader（无水印下载）、Summarizer（抽音 + ASR + LLM 总结）。

三层之间只通过明确的函数接口通信，任一层可独立替换（如 B站爬虫换 MediaCrawler、ASR 换模型）。

## 三、关键决策与依据

原设计文档给出了方向，落地时结合实测做了若干取舍：

1. **Agent 框架选 Agno**：相比 LangChain 更轻、原生支持 Ollama、运行时开销低，契合单机 8GB 的本地化目标。
2. **热榜自建而非依赖 MediaCrawler**：实测 MediaCrawler 原生只支持 search/detail/creator，**没有热榜类型**；因此 B站热榜改用平台「综合热门」REST API 自建。
3. **下载按平台分流**：f2 的强项是抖音/TikTok/微博，**不覆盖 B站**；故 B站用 yt-dlp（本身无水印），抖音/小红书留给 f2。
4. **B站爬虫直连 API 而非 MediaCrawler**：B站公开数据免登录、无 Playwright 开销，更轻更稳；MediaCrawler 留给风控更严的平台。
5. **ASR 用 faster-whisper**：基于 ctranslate2，**不依赖 torch**，显存占用低、速度快，优于原方案 openai-whisper。音频提取用 ffmpeg 子进程，替代较重的 moviepy。

## 四、分阶段实现

**Sprint 1｜底层工具打通（B站，无 AI）**
搭建工程骨架（uv + pyproject，重依赖走 optional extras）；实现 B站综合热门 / 排行榜 / 关键词搜索 / 创作者主页元数据抓取（含 WBI 签名与 buvid 指纹）；yt-dlp 无水印下载；ffmpeg 抽音；workspace 缓存 >7 天自动清理、下载随机抖动降风控。`crawl_cli.py` 验证通过。

**Sprint 2｜ASR + 云端总结**
`summarizer.py`：ffmpeg 抽音 → faster-whisper（GPU cuda/float16）转写 → DeepSeek 结构化总结。LLM 用 httpx 直调 OpenAI 兼容接口，云 / 本单点切换。**无音频轨自动降级**为仅元数据总结。`pipeline.py` 跑通硬编码全链路。

**Sprint 3｜Agent + UI**
`agent.py`：Agno Agent 装载三大工具 + 系统提示，自然语言驱动 Function Calling，支持多工具链式与出错反思。`ui.py`：Gradio 对话界面 + Markdown + 最新视频内嵌播放。实测 Agent 自主完成「抓热榜第1 → 下载 → 总结」，并对无语音视频如实降级标注。

## 五、踩到的坑与解决

| 问题 | 原因 | 解决 |
|---|---|---|
| 创作者接口 `code=-352` | B站风控，headless 无登录态 | 文档化需配 `BILI_COOKIE`；热门/搜索免登录可用 |
| 搜索返回 0 条 | 我误用 `result_type` 过滤，实际字段是 `type` | 改为按 `type=="video"` 过滤 |
| Agno 工具调用失败 | 异步工具不能用于同步 `agent.run()` | 全部改用 `agent.arun()` |
| DeepSeek 400「unknown variant developer」 | Agno 默认把 system 角色映射成 `developer` | `OpenAIChat(role_map={"system":"system",...})` 改回 |
| Gradio `Chatbot(type=)` 报错 | Gradio 6.x 移除该参数，messages 格式为默认 | 删除参数 |

## 六、测试与验证

- **单元测试**：18 项（pytest），覆盖元数据归一化、WBI 签名、日期过滤、文件名清理、平台识别、降级路径、Agent 工具装配、LLM 角色配置等纯逻辑；`ruff` lint 通过。
- **端到端**：B站热门 → 下载(50MB) → GPU ASR(中文) → DeepSeek 产出「核心观点 / 主要内容梳理」结构化总结；Agent 多工具链式与降级均实测通过。

## 七、后续工作（Sprint 4）

1. **本地化**：安装 Ollama + `qwen2.5:7b-instruct-q4`，`.env` 切 `local`；实现 8GB 显存分时复用（ASR 子进程跑完释放 + `torch.cuda.empty_cache()`，Ollama 常驻）。
2. **扩平台**：经子进程接入 MediaCrawler 抓抖音 / 小红书（需扫码登录、Cookie）；f2 做无水印下载。
3. **健壮性与体验**：补集成测试、超时与重试策略、UI 流式输出。

## 八、心得体会

整个项目最大的收获是「文档假设 ≠ 真实世界」：原设计把 MediaCrawler 当作万能入口，实测发现它没有热榜、不直接给无水印直链、B站也并非其强项——每一条都需要实测验证后重新选型。其次，第三方框架（Agno、Gradio）的默认行为常与国内模型 / 新版本 API 不匹配（system→developer 角色问题、Chatbot 参数变更），「读源码 + 最小复现」是最高效的定位手段。最后，分阶段交付、每阶段端到端可验证（而非堆功能），让系统始终保持「随时可用」的状态，是这次能稳步推进的关键。
