在 vLLM 中注入自定义解析器
核心思路：既然问题的根源是 vLLM 现有的 qwen3_xml 解析器不认识 Qwen3-Omni 的 <tool_call> 格式，那我们直接在 vLLM 侧写一个适配它的 Parser。这样就可以彻底干掉 llama_proxy 这个繁琐的中间层，恢复原生的高速流式输出。
vLLM 的工具调用解析器是高度可扩展的。你只需要在启动脚本中注册一个简单的自定义类即可。
1. 编写自定义解析器脚本 (custom_parser.py)
在你的 vLLM 服务器上创建一个 Python 文件：
code
Python
import json
import re
from typing import List, Optional, Union
from vllm.entrypoints.openai.tool_parsers.base import ToolParser, ToolParserManager
from vllm.entrypoints.openai.protocol import ExtractedToolCallInformation

@ToolParserManager.register_module("qwen3_omni_custom")
class Qwen3OmniToolParser(ToolParser):
    def __init__(self, tokenizer):
        super().__init__(tokenizer)
        # 用正则匹配 <tool_call> 标签内的内容
        self.pattern = re.compile(r"<tool_call>\s*(.*?)\s*</tool_call>", re.DOTALL)

    def extract_tool_calls(
        self, content: str
    ) -> Union[ExtractedToolCallInformation, None]:
        
        # 搜索是否包含工具调用标签
        match = self.pattern.search(content)
        if not match:
            return None

        json_str = match.group(1)
        try:
            # 尝试解析 JSON。因为你们提到嵌套问题，只要确保模型生成的是合法 JSON 即可解析
            tool_data = json.loads(json_str)
            
            tool_call = {
                "type": "function",
                "function": {
                    "name": tool_data.get("name", ""),
                    "arguments": json.dumps(tool_data.get("arguments", {})),
                },
            }
            return ExtractedToolCallInformation(
                tool_calls=[tool_call],
                # 关键：告诉 vLLM 剩下的哪些是纯文本内容（去除 tool_call 后的文本）
                content=content[:match.start()].strip() 
            )
        except json.JSONDecodeError:
            # 如果 JSON 不合法，交回给模型输出文本
            return None
2. 启动 vLLM 时挂载这个脚本
修改你的启动命令（如果是用 Python API 启动，直接 import custom_parser 即可）。如果是命令行，可以使用 vLLM 的 --tool-call-parser 配合注入：
code
Bash
# 启动时指定我们刚刚注册的 qwen3_omni_custom
vllm serve /path/to/model \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_omni_custom \
  ...
优势：
零中间层：彻底删除 llama_proxy，Agno 直接连 vLLM，链路最短。
真·流式输出：vLLM 的底层引擎会原生地处理 Tool Call 的 Streaming Chunk（包括 index 的正确分发），前端 UI 会丝滑流畅。
