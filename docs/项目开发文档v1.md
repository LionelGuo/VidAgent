
# 智能自媒体数据采集与多模态分析 Agent 系统
**—— 项目开发与架构设计文档 (V1.0)**

## 1. 项目概述 (Project Overview)
### 1.1 项目背景
在当前的短视频和流媒体时代，各平台（抖音、B站、小红书等）每天产生海量数据。本项目旨在研发一套稳定、高效的自动化系统，结合目前开源的爬虫工具（如 `MediaCrawler`）与大语言模型（LLM），实现对全网多平台视频数据的自动化采集、下载与智能归纳。

### 1.2 核心目标
1. **多平台支持**：支持小红书、抖音、快手、B站、微博等主流平台。
2. **场景化自动化**：
   - 自动获取某平台今日热榜 Top N 的视频并生成文字总结。
   - 自动定向抓取指定创作者（用户）今日发布的视频并生成总结。
3. **Agent 智能化交互**：打破传统命令行僵化限制，采用自然语言驱动（Prompt），由智能体（Agent）自主规划任务并调用底层工具。
4. **灵活部署架构**：支持云端大模型与本地化大模型的无缝切换，在单张 RTX 4060 (8GB显存) 笔记本上实现完整的本地化推理与运行。

## 2. 系统架构设计 (System Architecture)
系统采用**三层高度解耦**的模块化架构，从上到下依次为：交互层、智能体调度层、底层工具层。

### 2.1 架构分层
* **UI 交互层 (Presentation Layer)**
  * 技术栈：`Gradio` 
  * 功能：提供类似 ChatGPT 的对话界面。支持用户输入自然语言指令，支持在对话框中直接渲染 Markdown 文本和播放本地 `.mp4` 视频。
* **Agent 调度层 (Orchestration Layer)**
  * 技术栈：`LangChain` 或 `Agno` + `OpenAI API 标准客户端`
  * 功能：系统的大脑。负责意图识别、任务拆解、Tool Calling（工具调用）以及多模态结果聚合。
* **底层工具层 (Tools / Functions Layer)**
  * **爬虫适配器 (Crawler Adapter)**：封装 `MediaCrawler`，执行免登录/扫码登录的数据抓取。
  * **下载器 (Downloader)**：基于 `aiohttp` 的异步文件下载。
  * **多媒体处理 (Media Processor)**：基于 `moviepy` 和 `Whisper` 的音频提取与 ASR（语音识别）。

## 3. 核心模块与 API 规范 (Module Specifications)

为了实现 Agent 的工具调用（Function Calling），底层功能将被封装为标准的 Python 函数接口。

### 3.1 Tool 1: 视频信息检索 (`search_and_fetch_videos`)
* **功能**：根据条件获取视频的基础元数据。
* **输入参数**：
  * `platform` (str): 平台名称 (bilibili, douyin, xiaohongshu等)
  * `task_type` (str): 任务类型 (hot_board, user_homepage)
  * `target_id` (str): 关键词或用户UID (热榜模式可为空)
  * `date_filter` (str): 时间过滤条件 (如 "today")
  * `limit` (int): 抓取数量上限
* **输出 (JSON)**：包含 `[{"video_id", "title", "desc", "publish_time", "video_url"}]` 的列表。

### 3.2 Tool 2: 视频无水印下载 (`download_video`)
* **功能**：接收视频直链，下载文件到本地工作流目录。
* **输入参数**：
  * `video_url` (str): 视频播放直链
  * `file_name` (str): 预期保存的文件名
* **输出 (JSON)**：包含 `{"status": "success", "local_path": "./workspace/xxx.mp4"}`。

### 3.3 Tool 3: 视频内容解析与总结 (`extract_and_summarize`)
* **功能**：提取本地视频音频，进行语音转文字，并对全量文本进行归纳。
* **输入参数**：
  * `local_path` (str): 本地视频路径
  * `metadata` (dict): 包含标题和简介的字典
* **输出 (str)**：结构化的总结文本（如：1.核心观点；2.主要内容梳理）。

## 4. 部署与硬件适配方案 (Deployment Strategy)

针对设备条件（**RTX 4060 Laptop, 8GB VRAM**），采用“前期云端，后期本地分时复用”的部署策略。

### 4.1 接口无缝切换设计
全系统统一使用 `OpenAI 兼容协议` 进行 LLM 调用。
* **开发调试期（云端）**：
  使用国内高性价比大模型（如 DeepSeek-V3 / 阿里云 Qwen-Max）。
  `client = OpenAI(api_key="sk-xxx", base_url="https://api.deepseek.com/v1")`
* **最终部署期（纯本地）**：
  使用 `Ollama` 部署 `Qwen2.5-7B-Instruct (4-bit GGUF量化版)`。
  `client = OpenAI(api_key="empty", base_url="http://localhost:11434/v1")`

### 4.2 极限显存调度策略 (8GB VRAM 解决方案)
由于 8GB 显存无法同时容纳 LLM 和 ASR 模型，必须实现**显存的分时复用（按需加载与释放）**：
1. **ASR 阶段**：通过 Python 子进程启动 `Whisper (Base/Small 模型)`，占用约 1.5GB ~ 2GB 显存，处理完毕后**强行销毁该进程**，并调用 `torch.cuda.empty_cache()` 释放显存。
2. **LLM 阶段**：启动 Ollama 调用量化版 LLM（占用约 4.5GB ~ 5GB 显存），进行文本总结和 Agent 推理。

## 5. 异常处理与系统健壮性 (Robustness & Constraints)

### 5.1 爬虫风控与限流
* **延时机制**：在并发下载模块中，强制增加 `sleep(random.uniform(2, 5))` 的随机抖动。
* **状态保持**：复用 `MediaCrawler` 提供的浏览器 Cookie 缓存机制，减少频繁登录触发的风控滑块。

### 5.2 Agent 兜底机制 (Fallback)
* **最大重试次数**：设置 Agent 错误反思机制（Max Retries = 3）。若工具调用返回报错（如 JSON 解析失败、下载链接失效），提示 LLM 进行自我修正。
* **优雅降级**：若遇到极少数没有声音的视频导致 Whisper 报错，系统应捕捉异常，仅依赖“视频标题+简介”进行降级总结，而不是导致整个程序崩溃。

### 5.3 磁盘存储管理
* **生命周期管理**：设立 `workspace/` 缓存目录。每次任务开始前，或任务运行满 7 天后，自动清理历史 `.mp4` 和 `.mp3` 缓存文件，防止磁盘写满。

## 6. 项目开发计划 (Milestones)

项目开发预计分为 4 个 Sprint（迭代周期）：

* **Sprint 1: 底层工具打通 (Week 1)**
  * 跑通开源 `MediaCrawler`，成功获取 B站/抖音 的指定视频元数据。
  * 编写基于 `aiohttp` 的异步下载模块。
  * 编写 `moviepy` 音频提取脚本。
* **Sprint 2: AI 分析与云端联调 (Week 2)**
  * 跑通 Whisper 语音转文字。
  * 接入云端大模型 API，基于固定的 Python 脚本完成“抓取 -> 下载 -> 总结”的硬编码流水线。
* **Sprint 3: Agent 架构升级与 UI 搭建 (Week 3)**
  * 引入 Agent 框架，将 Sprint 1/2 的脚本封装为 Tools。
  * 编写系统 Prompt，测试自然语言驱动的工具调用能力。
  * 使用 Gradio 搭建多模态 Web 交互界面。
* **Sprint 4: 本地化部署与性能优化 (Week 4)**
  * 部署 Ollama，切换大模型至本地 Qwen2.5。
  * 优化 8GB 显存的调度逻辑，解决并发 OOM（爆显存）问题。
  * 完善异常处理代码，编写最终实习总结报告。
