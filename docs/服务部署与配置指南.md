# VidAgent 服务部署与配置指南

## 架构总览

```
┌─────────────── AutoDL 服务器 (RTX 3090 48GB) ───────────────┐
│                                                              │
│  vLLM-Omni :6006                                              │
│  ├─ Agent 主模型（文本 + tool calling）                        │
│  └─ 多模态模型（音频 + 帧 → 视频总结）                          │

                       │

│  llama_proxy :8081  ←──→  vLLM-Omni :8443                   │
```

## 一、服务器端

### 1.1 SSH 登录

```bash
ssh -p <端口> root@connect.westd.seetacloud.com
```

AutoDL 实例需以**有卡模式**开机。

### 1.2 模型文件

模型路径：`/root/autodl-tmp/Qwen3-Omni-30B-AWQ`

| 文件 | 说明 |
|------|------|
| `config.json` | 模型架构：`qwen3_omni_moe`，量化：`compressed-tensors` INT4 |
| `*.safetensors` | 权重文件（~27.5 GB，6 个分片） |
| `preprocessor_config.json` | 音频/图像输入上限（已修改为支持 1h 音频） |
| `tokenizer.json` | Tokenizer |

### 1.3 启动 vLLM-Omni

vLLM 以 **bare mode** 运行（不传 `--enable-auto-tool-choice` / `--tool-call-parser`），让 Qwen3-Omni 自由输出文本（含 `<tool_call>` XML），工具调用的解析和转换由本机 SSE Relay 完成。

```bash
export VLLM_MAX_AUDIO_DECODE_DURATION_S=3600

nohup /root/miniconda3/bin/vllm-omni serve \
  /root/autodl-tmp/Qwen3-Omni-30B-AWQ \
  --port 6006 \
  --gpu-memory-utilization 0.85 \
  --max-num-batched-tokens 16384 \
  --max-num-seqs 8 \
  --enable-prefix-caching \
  > /root/autodl-tmp/server.log 2>&1 &
```

也可直接使用仓库脚本：

```bash
bash /root/autodl-tmp/VidAgent/scripts/start_vllm_bare.sh
```

#### 参数说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `VLLM_MAX_AUDIO_DECODE_DURATION_S` | `3600` | 环境变量，允许最长 60 分钟音频输入（默认仅 600s） |
| `--port` | `6006` | 服务监听端口 |
| `--gpu-memory-utilization` | `0.85` | GPU 显存使用比例（48GB × 0.85 ≈ 41GB 给 KV cache） |
| `--max-num-batched-tokens` | `16384` | 单次 batch 最大 token 数，提升 decode 阶段吞吐 |
| `--max-num-seqs` | `8` | 最大并发序列数 |
| `--enable-prefix-caching` | — | 复用相同前缀的 KV cache（Agent 长 system prompt 跨轮次受益） |

#### 启动耗时

约 5-7 分钟（208s 加载权重 + 112s 编译/CUDA graph 预热）。

#### 检查就绪

```bash
curl -s http://localhost:6006/health
# 返回空响应 + HTTP 200 = 就绪
```

### 1.4 已修改的配置

**`preprocessor_config.json`**：`n_samples` 从 4,800,000（300s）增至 57,600,000（3600s），支持 1 小时音频。

在 AutoDL 控制台 → 实例 → 自定义服务，添加：

| 字段 | 值 |
|------|-----|
| 服务端口 | `6006` |
| 外部端口 | `8443` |

## 二、本机端

### 2.1 `.env` 配置

```bash
# Agent 主模型（通过代理，因为 vLLM qwen3_xml parser 不解析 Qwen3-Omni 的 tool_call）
OPENAI_BASE_URL=http://127.0.0.1:8081/v1
OPENAI_API_KEY=not-needed
LLM_MODEL=/root/autodl-tmp/Qwen3-Omni-30B-AWQ

# 多模态推理（直连 vLLM-Omni，无需代理）
MULTIMODAL_BASE_URL=https://u<userid>-<instance>.westd.seetacloud.com:8443/v1
MULTIMODAL_MODEL=/root/autodl-tmp/Qwen3-Omni-30B-AWQ

# 多模态模式开关
LLM_MULTIMODAL=true

# Agent 工具链
LLM_PROVIDER=cloud
```

#### 关键分离

| 功能 | 端点 | 原因 |
|------|------|------|
| **Agent 文本 + tool calling** | `proxy :8081` → vLLM | proxy 负责 `<tool_call>` XML → OpenAI tool_calls 转换 |
| **多模态总结** | vLLM `:8443` 直连 | 不需要 tool calling，流式透传即可，无额外延迟 |

### 2.2 启动代理

```bash
cd /home/lionel/Code/VidAgent

.venv/bin/python scripts/llama_proxy.py \
  --port 8081 \
  --backend https://u<userid>-<instance>.westd.seetacloud.com:8443 \
  > /tmp/proxy.log 2>&1 &
```

#### 代理核心功能

```
请求到达
  ├─ 保存 stream 标志 → 删除 stream_options（vLLM 校验）
  ├─ 转发到 vLLM（保持 stream=true）
  │
  ├─ 流式处理 vLLM 响应：
  │   ├─ 缓冲首段 ~20 chars 判断类型
  │   │   ├─ 以 < 或 { 开头 → tool_call → 缓冲完整响应 → 提取 tool_calls → 重写 SSE
  │   │   └─ 普通文本 → 立即透传 vLLM 的 SSE chunks（零延迟）
  │   └─ tool_call 提取使用大括号计数算法（处理任意嵌套 JSON）
  │
  └─ HTTP/1.1 协议（OpenAI SDK 要求 HTTP/1.1 才处理 SSE 流）
```

### 2.3 启动 UI

```bash
cd /home/lionel/Code/VidAgent
uv run python -m vidagent.ui
```

Gradio 界面在 `http://127.0.0.1:7860`。

### 2.4 一键启动脚本

```bash
#!/bin/bash
# start_all.sh — 启动所有本机服务

cd /home/lionel/Code/VidAgent
BACKEND="https://u<userid>-<instance>.westd.seetacloud.com:8443"

# 1. 启动代理

  --port 8081 --backend "$BACKEND" \
  > /tmp/proxy.log 2>&1 &
echo "Proxy PID: $!"

# 2. 启动 UI
uv run python -m vidagent.ui
```

## 三、模型性能特征

### 3.1 实测速度

| 场景 | tok/s | 说明 |
|------|-------|------|
| 终端直接流式 | **~300** | `scripts/bench_stream.py` 直接连 vLLM |
| 通过代理 | **~300** | 无损耗（纯文本透传模式） |
| Agno Agent（API 层） | **~160** | 含 prompt 构造 + 系统消息开销 |
| UI 端感知 | **~300** | 100ms 定时渲染，与模型速度一致 |

### 3.2 GPU 利用率说明

Qwen3-Omni-30B-A3B 是 MoE 模型（30B 总参数，每 token 仅激活 3B）。单请求时 GPU SM 利用率约 15-30%，这是**架构固有的正常表现**，瓶颈在显存带宽（3090 ~936 GB/s），不在计算单元。多请求并发时利用率会提升。

### 3.3 输入上限

| 模态 | 上限 | 说明 |
|------|------|------|
| 音频 | **3600s (1h)** | 已修改 preprocessor 的 `n_samples` |
| 图像 | 12.8MP/帧 | `max_pixels: 12845056` |
| 视频帧 | 768 帧 | `max_frames: 768` |
| Token 预算 | 65,536 | 所有模态共享 |
| 音频 token 消耗 | ~13 tok/s | 1h 音频 ≈ 46,800 tokens |

## 四、故障排查

### 代理返回 `Stream options can only be defined when stream=True`

代理未正确删除 `stream_options`。检查代理日志，确保启动命令正确。

### UI 只输出 "思考中" 后停止

1. 确认代理使用 HTTP/1.1：`curl -sv http://127.0.0.1:8081/health 2>&1 | grep HTTP`
2. 确认 vLLM 服务器就绪：`curl https://<url>:8443/health`

### 工具调用不执行（输出 `<tool_call>` XML 文本）

1. 确认代理在运行：`ps aux | grep llama_proxy`
2. 确认 `.env` 的 `OPENAI_BASE_URL` 指向代理 `:8081` 而非直连 vLLM
3. 检查代理日志：`cat /tmp/proxy.log`

### GPU 显存不足

当前配置 `--gpu-memory-utilization 0.85`，已占 48GB × 0.85 ≈ 41GB。如需调整：

```bash
# 降低 KV cache 配额（会减小 max_model_len）
--gpu-memory-utilization 0.75

# 或限制最大并发
--max-num-seqs 4
```
