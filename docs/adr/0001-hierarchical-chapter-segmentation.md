# ADR-0001: 视频章节时间轴的分段策略

**日期**: 2026-08-09
**状态**: 提议中 (proposed)

## 背景

VidAgent 需要实现「章节时间轴 (Chapter Timeline)」功能——在视频进度条上标记话题分段，对标 B 站「看点」。

初始假设是 Qwen3-Omni 能够原生从音频+帧中感知时间位置。但 SONIC-O1 benchmark 数据显示，Qwen3-Omni-30B-A3B 在时间定位任务上仅取得 2.8% R@0.5，表明原生时间感知是显著短板。

## 关键约束

1. **完整音频可单请求处理**：16kHz mono `-q:a 7` mp3 下，1 小时视频 ≈ 15MB mp3 ≈ 20MB base64。Qwen3-Omni 通过音频编码器处理音频（不经过 text tokenizer），不受 32K text token 限制。B 站典型视频（3-30 分钟）的完整音频在单请求中完全可处理。当前代码已有此能力（`_MAX_AUDIO_B64_KB = 20 * 1024`）。
2. **不做逐段 LLM 调用**：对每个细粒度片段分别调用模型生成 caption，代价高、延迟大。候选锚点通过传统快速方法提取，模型只在最终阶段调用一次（做语义聚合）。
3. **V1 不做 zoom-in 验证**：先验证基础 pipeline 可行性。局部高密度采样验证推迟到 V2。

## 决策

采用**候选锚点 + 模型单次聚合 (Candidate-Anchored Single-Pass Aggregation)**：

1. **工程侧 — 混合边界检测**：ffmpeg scene detection（画面突变）+ audio silence detection（语音停顿）+ 强制兜底切分。输出候选边界时间戳列表 `[0, 45, 120, 190, ...]`（单位：秒）。在候选边界处抽取稀疏关键帧（替代均匀采样）。
2. **模型侧 — 约束选择 + 时间线总结**：完整音频 + 候选帧（附时间戳标注）+ 候选边界列表 → 单次模型调用。System prompt 强制约束：章节边界只能从候选列表中选取（消除时间戳幻觉）。模型输出：章节时间轴 JSON + 按时间顺序的结构化总结。
3. **边界精度** = 候选边界粒度（30-90 秒）。解析阶段校验：若模型输出的时间戳不在候选列表中，自动修正为最近的候选边界。

## 替代方案

### 方案 A：固定时长切分 + 逐段总结 → 合并
- 每 2-3 分钟切一段 → 每段独立总结 → 合并
- **拒绝原因**：段间无上下文共享；合并阶段模型看不到原始音视频，准确性下降

### 方案 B：模型原生时间定位
- 完整音频 + 帧 → 模型自主输出带时间戳的章节
- **拒绝原因**：Qwen3-Omni 在此任务上表现极差（2.8% R@0.5）

### 方案 C（选定）：候选锚点 + 模型单次聚合
- 工程侧提取候选边界 + 稀疏帧 → 模型在完整音频上下文中从候选列表中选章节边界 → 输出时间线
- 优点：全局上下文完整（完整音频）、边界可校验（强制候选列表约束）、单次模型调用（延迟低）
- 缺点：场景检测对固定机位视频效果弱（需 silence detection + 强制切分兜底）

## 影响

- **`utils/frames.py`**：新增 `detect_boundaries()` — 混合边界检测（scene + silence + 兜底）。帧提取改为在候选边界处采样。
- **`tools/summarizer.py`**：新 prompt — 要求模型输出 `{chapters: [{start, end, title}], timeline_summary}` 格式。System prompt 强制边界只能从候选列表选取。
- **音频处理**：保持不变（`extract_audio()` 已支持完整音频）。
- **前端**：DetailPanel 新增章节时间轴 UI 组件（视频进度条标记点）。
- **V2 预留**：`zoom_in_verify` 局部验证工具、Thinking 变体适配、思维导图 UI。
